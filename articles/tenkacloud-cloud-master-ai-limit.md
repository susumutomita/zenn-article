AWSのAPI呼び出しを見張り、不審な操作を見つけたら知らせる。Amazon GuardDutyのような脅威検知サービスの仕事を、プレイヤーが自分でやってみるブラウザゲームを作りました。[TenkaCloud](https://github.com/susumutomita/TenkaCloud)のサイトで公開している[APIの番人。｜目指せクラウドマスター](https://tenkacloud.com/cloud-master)です。この記事では、まずこのゲームの遊び方と作った理由を紹介します。そのあとで、AIエージェントに自動プレイさせて速度の限界を調べたら、Lv105から先が難しくなっていなかった話を書きます。

## 脅威検知サービスになって遊ぶ

ゲームを開くと、最初に「脅威検知サービスの気持ちになって、不審なAPIリクエストを弾き飛ばそう」と表示されます。プレイヤーは本番のAWS環境を見張る役です。顧客データや監査ログを守る想定の環境で、次々に届く操作を見て、異変だけを見つけます。ブラウザだけで遊べて、インストールやAWSアカウントは要りません。

画面の上から、AWSの操作を書いたカードが落ちてきます。カードには、API名とSDK形式の引数の抜粋、対象のリソースや用途が書いてあります。API呼び出しのほかに、CloudTrailのログや通信の記録といった合成データのカードもあります。脅威検知サービスが受け取るような記録を、人が読める形にしたものです。

ルールは3つだけです。

- 危険な操作のカードだけをタップし、正常なカードはそのまま下まで流す
- ライフは3つで、見逃しか誤タップで1つ減る
- 危険の検知と正常の通過を合わせて5枚正解するとレベルが上がり、落下が速くなる

見逃しは検知漏れ、誤タップは誤検知です。どちらもライフが減るので、怪しいものを片端からタップする作戦は通用しません。

### カードはGuardDutyのfindingが元になっている

カードの題材は、GuardDutyの公開ドキュメントにあるfindingとシグナルです。公開スナップショットの211の標準findingと35のCloudTrailシグナルに、Runtime Monitoringの章にある7シグナルを加えています。現在は260の演習と、正常と要確認を合わせた520の基本ケースがあります。

たとえば、`ModifyInstanceAttribute`で`DisableApiTermination.Value: true`を指定するカードが出てきます。インスタンスを誤って終了させないための設定で、それ自体はよく使います。ところが、このカードの対象は廃止予定の検証用VMで、状況には削除の妨害を監視していると書いてあります。この組み合わせなら危険と判断してタップします。

同じAPIでも、対象や状況によって正常か危険かが変わります。そのため、API名だけでは判定できず、引数と状況を読む必要があります。ゲームの説明にも「API名だけで危険と判定しません」と書いています。

ただし、これは学習用の演習です。ゲームはAWSへのリクエストを一切送りません。判定はゲーム内で示した演習方針に沿うかどうかで、実際のGuardDutyの判定式を再現したものではありません。

### 間違えたときに学べる

見逃しや誤タップをすると、ゲームはその場で止まります。間違えたカードについて、操作の意味と判断の決め手になった値、短い解説を表示します。AWSの公式ドキュメントへのリンクも付けています。「続ける」を押すと、止まった位置から再開します。正解したときも、画面の下に短い理由が出ます。

ゲームを終えると、そのラウンドで出たリクエストを振り返れます。英語にも対応しています。

## なぜ作ったのか

TenkaCloudは、チームで問題を解いて得点と順位を競うOSSの競技基盤です。サイトの企業向けの説明では、セキュリティ研修の課題を次のように書いています。

> これまでのセキュリティ研修はスライド中心の e-ラーニングが多く、手を動かすインタラクティブな研修は作るのも運営するのも大変でした。AI の進化で、セキュリティは専門家だけの関心ごとではなくなっています。それでも、見て読むだけの研修にはゲーム性がなく、定着しにくいままです。

TenkaCloud本体で大会を開くには、主催者の準備が必要です。このゲームは、その手前でクラウドセキュリティの判断を一人で試せる入り口です。サイトのトップページでは、「3ライフと見逃し解説で学べます」と紹介しています。

## 何が面白いのか

面白さは、脅威検知サービスが抱える難しさを、速さとして体験できるところにあります。

記録は待ってくれません。カードは何枚も同時に落ちてきて、レベルが上がるほど速くなります。それでも、API名だけを見てタップすると誤検知になります。見逃せば検知漏れです。引数と状況を読む時間と、カードが落ちきるまでの時間との勝負になります。

生存時間は0.1秒単位で表示され、自己ベストは端末に保存されます。連続で検知するとコンボの表示が伸びます。結果はXに投稿でき、知り合いと生存時間を比べられます。間違えると解説が出るので、負けた理由がその場でわかり、もう1回遊びたくなります。

ここからは、この「番人」の役を自動プレイに任せて、ゲームの速度設計を調べた話です。

## 自動プレイの方法

SNSに載せる動画を作るため、AIエージェントにこのゲームを自動プレイさせ、どこまで速くなるかを試しました。最初に、何を測ったのかをはっきりさせておきます。

AIエージェントには、Playwrightで動く自動プレイスクリプトを書かせました。このスクリプトは、カードの文字を読んで危険かどうかを判断していません。ゲーム内部の状態から危険なカードを特定し、そのカードの位置を本物のマウスイベントでクリックします。ゲームの状態は書き換えません。

つまり、これは判断力の測定ではありません。判断が常に正しく、反応も速いプレイヤーを用意して、ゲームの速度設計がどこまで持つかを確かめる負荷試験です。

時計は仮想化しました。`performance.now()`を差し替え、1/60秒ずつ進めてから描画を待ちます。毎フレームのスクリーンショットに時間がかかっても、ゲームからは理想的な60Hzの画面に見えます。そのため、記事中の時間はゲーム内の時間です。修正後の実行では、ゲーム内の27分に実時間で1時間40分以上かかりました。

## 修正前の挙動：表示はLv367、速度はLv118

修正前のバージョンで、横長の画面を使って自動プレイしました。ゲーム内585秒の時点で、画面の表示はLv367、ミスは0でした。ただし、内部で速度の計算に使うレベルは118で、落下時間は600msのまま変わっていませんでした。

![修正前のバージョンで、画面にLv367と585.0秒が表示されている](/images/tenkacloud-cloud-master-ai-limit/before-lv367.jpg)

別に長く回した実行では、ゲーム内約1,020秒で表示がLv1237になりました。このときも速度の計算に使うレベルは225で、落下時間は600msでした。表示のレベルがいくら上がっても、難しさは変わっていませんでした。

原因は2つありました。

### 落下時間に600msの下限があった

落下時間と出現間隔は、[`recognition.js`](https://github.com/susumutomita/TenkaCloud/blob/254b2d12b1d1e1cd7e971a7b3effbc619b0cdd11/landing/cloud-master/recognition.js)の段階表で決まります。Lv1の落下時間は10秒で、Lv28で4.2秒になります。Lv28から先は、1レベルごとに0.975倍になります。

修正前のコードには、落下時間に600ms、出現間隔に100msの下限がありました。4.2秒に0.975倍を繰り返すと、Lv105前後で600msに達します。それ以降は、レベルが上がっても速くなりません。コメントによると、600msは入力ガード100msを6回分確保するための値でした。

### 速度のレベルが表示に追いつかなかった

このゲームでは、5問正解するたびに表示のレベルが1つ上がります。一方、速度の計算に使うレベルは、新しいルールを知らせる通知を読み終えたときに上がります。通知は3秒表示し、1秒の猶予を置きます。

修正前は、通知1回につき速度のレベルが1つしか上がりませんでした。自動プレイのように4秒で5問以上を正解し続けると、表示のレベルだけが先に進みます。修正前の2つの実行で見えた367と118、1237と225の差は、このずれです。

## 修正：Lv105から先は平方根で縮める

[PR #3490](https://github.com/susumutomita/TenkaCloud/pull/3490)では、Lv105までの曲線をそのまま残し、その先をべき乗の曲線でつなぎました。

```js
// landing/cloud-master/recognition.js（抜粋）
export const TAIL_START_LEVEL = 105;
export const TAIL_FALL_MS = 600;
export const TAIL_INTERVAL_MS = 100;

const tail = stage.level === 28 && current > TAIL_START_LEVEL;
const scale = tail
  ? Math.sqrt(TAIL_START_LEVEL / current)
  : stage.level === 28
    ? 0.975 ** Math.max(0, current - 28)
    : 1;
```

Lv105より上では、落下時間は`600ms × √(105 / Lv)`、出現間隔は`100ms × √(105 / Lv)`になります。固定の下限はありません。

実際にカードが出る間隔は、出現間隔と「落下時間÷画面に置ける枚数」の長いほうです。画面に置ける枚数は画面サイズで決まり、上限は6枚です。新しいカードは描画1フレームにつき最大1枚しか出ません。

| Lv | 落下時間 | 3枚の画面での出現間隔 | 6枚の画面での出現間隔 |
| --- | ---: | ---: | ---: |
| 105 | 600ms | 200ms | 100ms |
| 500 | 275ms | 92ms | 46ms |
| 1000 | 194ms | 65ms | 32ms |
| 3395 | 105.5ms | 35ms | 18ms |

6枚の画面でも、60Hzなら1フレーム（約16.7ms）より短い間隔では出ません。

速度のずれも直しました。新しいルールの通知はLv7で出そろうので、それ以降の通知は1段ずつではなく、最新の表示レベルへまとめて進めます。

## 速くしたことで必要になった安全策

落下時間を短くすると、別の問題が出てきます。PRでは次の対策も入れています。

- 入力ガードを固定の100msから「100msと落下時間の1/6の短いほう」へ変えた
- 新しいカードは、描画されて押せる状態になったと確認できるまで採点しない
- 速度が大きく上がったときに古いカードが残っていたら、それがなくなるまで新しいカードを止める
- 描画が追いつかない速さに達したら、`測定上限到達`としてゲームを終える

最後の測定上限は、新しく追加した[`render-budget.js`](https://github.com/susumutomita/TenkaCloud/blob/254b2d12b1d1e1cd7e971a7b3effbc619b0cdd11/landing/cloud-master/render-budget.js)で判定します。直近60〜120回の描画間隔から90パーセンタイルを求め、落下時間がその3倍を下回ったら終了します。

安定した60Hzなら描画間隔は約16.7msなので、落下時間が50msを切ったところで終わります。計算上はLv15,120あたりです。端末やブラウザーによって描画間隔は変わるので、この値も変わります。

測定上限で終わった記録は、ミスや通常のBESTとは別に、測定条件と一緒に保存します。端末の表示の限界であって、判断ミスではないからです。

## 修正後の結果：Lv3458、ミス0

修正を取り込んだmain（254b2d1）を手元で配信し、540×800の画面で自動プレイし直しました。この画面サイズでは、カードは3枚まで置けます。

![修正後のバージョンで、Lv3458、1627.9秒、596830点、ライフ3つが表示されている](/images/tenkacloud-cloud-master-ai-limit/after-lv3458.jpg)

- ゲーム内1627.9秒で表示はLv3458、得点は596,830
- ミスは0で、ライフは3つとも残った
- 止めた時点の落下時間は105.5msで、カードは約35msごとに出ていた
- Lv1000以降、カードが描画されてからクリックするまでは毎回33ms（2フレーム）で、ボタンが押せる状態になった最初の機会に押していた

ゲームオーバーではなく、こちらで止めました。測定上限のLv15,120あたりまでは、このペースだとまだかなりかかるからです。

修正前とは違い、速度の計算に使うレベルは表示とほぼ同じでした。止める直前のログでは、表示がLv3399のとき速度の計算に使うレベルは3395です。残りの差は、通知を読ませる4秒の間に進んだぶんです。

## 残っている課題

回してみて、ほかにも気になる点がありました。

1つ目は、測定上限で終わった記録がBESTに残らないことです。意図した仕様ですが、限界まで遊んだプレイヤーから見ると、自己ベストが更新されないのは少しわかりにくい挙動です。

2つ目は、画面に置けるカードの枚数が画面サイズで変わることです。上の表のとおり、同じレベルでも3枚の画面と6枚の画面では出現間隔が倍違います。記録を比べるなら、端末と画面サイズ、ブラウザーをそろえる必要があります。

## おわりに

Lv105から先で難しさが止まっていることは、人が遊ぶだけでは気づきにくい問題でした。判断が常に正しいプレイヤーで回すと、速度の下限と、表示と内部のレベルのずれがすぐに見えました。

ただし、この自動プレイは答えを内部の状態から読んでいます。人やAIの判断力を示す数字ではありません。ゲームの曲線と描画の限界を確かめる道具として使うのがよいと考えています。
