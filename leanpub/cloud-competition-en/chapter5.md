`template.yaml` is the CloudFormation template deployed to one team's AWS account. For `hello-world`, it creates one SSM Parameter and an IAM role that lets participants read it.

See the completed [template.yaml](https://github.com/susumutomita/TenkaCloudChallenge/blob/main/challenges/hello-world/template.yaml).

## Structure of template.yaml

A CloudFormation template can be read in four sections:

```yaml
AWSTemplateFormatVersion: "2010-09-09"
Description: >
  TenkaCloud hello-world Challenge.

Parameters:
  # Values passed by TenkaCloud during deployment

Resources:
  # Resources created in the team AWS account

Outputs:
  # Values used by scoring and the Participant Portal
```

`Parameters` are inputs, `Resources` are the objects to create, and `Outputs` are the values returned to TenkaCloud.

## Values Received from TenkaCloud

`hello-world` receives four Parameters.

```yaml
Parameters:
  NamePrefix:
    Type: String
    MinLength: 5
    MaxLength: 80
    AllowedPattern: "^tc-[a-z0-9]+(-[a-z0-9]+)+$"

  TenkaCloudAccountId:
    Type: String
    AllowedPattern: "^[0-9]{12}$"

  ExternalId:
    Type: String
    NoEcho: true
    MinLength: 16

  FlagSeed:
    Type: String
    NoEcho: true
    MinLength: 8
    MaxLength: 64
    AllowedPattern: "^[A-Za-z0-9]+$"
```

`NamePrefix` prevents resource name collisions between teams.

TenkaCloud uses `TenkaCloudAccountId` and `ExternalId` when assuming the participant role. Requiring `ExternalId` prevents an unintended third party from assuming it.

`FlagSeed` is a random value generated by TenkaCloud for each deployment. A later chapter passes `__RANDOM_PASSWORD__` from `metadata.json`.

## Participant IAM Role

Use `ParticipantViewerRole` as the logical ID. TenkaCloud reads its ARN from an Output and uses the role to send participants into AWS.

The role needs two types of permissions:

1. A trust policy that allows TenkaCloud's AWS account to assume the role with the correct `ExternalId`
2. Permissions that let participants read only their own SSM Parameter

The trust policy has this form:

```yaml
ParticipantViewerRole:
  Type: AWS::IAM::Role
  Properties:
    AssumeRolePolicyDocument:
      Version: "2012-10-17"
      Statement:
        - Effect: Allow
          Principal:
            AWS: !Sub "arn:aws:iam::${TenkaCloudAccountId}:root"
          Action: sts:AssumeRole
          Condition:
            StringEquals:
              sts:ExternalId: !Ref ExternalId
    MaxSessionDuration: 3600
    ManagedPolicyArns:
      - arn:aws:iam::aws:policy/SignInLocalDevelopmentAccess
```

`SignInLocalDevelopmentAccess` is required by the temporary AWS sign-in path provided by TenkaCloud. Do not remove this catalog-wide requirement for an individual problem.

The permissions required to open CloudShell are also mandatory across the catalog.

```yaml
Policies:
  - PolicyName: ProblemSpecific
    PolicyDocument:
      Version: "2012-10-17"
      Statement:
        - Sid: OpenCloudShellSession
          Effect: Allow
          Action:
            - cloudshell:CreateEnvironment
            - cloudshell:CreateSession
            - cloudshell:GetEnvironmentStatus
            - cloudshell:StartEnvironment
            - cloudshell:StopEnvironment
            - cloudshell:DeleteEnvironment
            - cloudshell:PutCredentials
          Resource: "*"
```

Restrict SSM read access to the participant's own `NamePrefix`.

```yaml
- Sid: ReadOwnSsmParameters
  Effect: Allow
  Action:
    - ssm:GetParameter
    - ssm:GetParameters
    - ssm:GetParametersByPath
  Resource: !Sub "arn:aws:ssm:*:*:parameter/${NamePrefix}/*"
```

The Parameter detail page in the AWS Console also calls `ssm:DescribeParameters`. This API cannot be restricted by resource ARN, so add a separate read statement. TenkaCloud assumes that each team has a separate AWS account.

```yaml
- Sid: DescribeOwnParameters
  Effect: Allow
  Action: ssm:DescribeParameters
  Resource: "*"
```

## Store the Flag in an SSM Parameter

```yaml
HelloParameter:
  Type: AWS::SSM::Parameter
  Properties:
    Name: !Sub "/${NamePrefix}/hello"
    Type: String
    Value: !Sub "TC{${FlagSeed}}"
    Description: !Sub "TenkaCloud hello-world flag parameter (${NamePrefix})."
    Tier: Standard
```

Participants read a value in the form `TC{...}`. Its content comes from `FlagSeed`, so it cannot be inferred from `NamePrefix`.

## Return Outputs to TenkaCloud

```yaml
Outputs:
  ParameterName:
    Value: !Ref HelloParameter

  ParameterValue:
    Value: !GetAtt HelloParameter.Value

  ParameterConsoleUrl:
    Value: !Sub "https://${AWS::Region}.console.aws.amazon.com/systems-manager/parameters/${NamePrefix}/hello/description?region=${AWS::Region}&tab=Table"

  NamePrefix:
    Value: !Ref NamePrefix

  ParticipantViewerRoleArn:
    Value: !GetAtt ParticipantViewerRole.Arn
```

Each Output has a different consumer.

| Output | Consumer | Purpose |
| --- | --- | --- |
| `ParameterName` | Participant, organizer | Name of the created Parameter |
| `ParameterValue` | Scoring engine | Correct answer |
| `ParameterConsoleUrl` | Participant | Detail page in the AWS Console |
| `NamePrefix` | TenkaCloud | Team-specific prefix |
| `ParticipantViewerRoleArn` | TenkaCloud | Role used to send participants into AWS |

Participants do not have permission to read CloudFormation Outputs directly, so they cannot obtain the answer from `ParameterValue`. The next chapter connects this Output to flag scoring in `metadata.json`.
